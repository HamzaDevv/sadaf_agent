# Known Issue: Groq SDK AsyncClient.aclose Warning

## Description
When running the `Sadaf-BOT` test suite (specifically `test_stress_human.py`), you might encounter a warning during test teardown if you don't have the explicit filterwarnings set in `pytest.ini`.

The warning looks like this:
```text
RuntimeWarning: coroutine 'AsyncClient.aclose' was never awaited
# OR
RuntimeWarning: coroutine 'BaseApiClient.aclose' was never awaited
```

## Root Cause
The `groq-python` SDK is auto-generated using **Stainless API**. Under the hood, it uses `httpx.AsyncClient` for async HTTP requests, which maintains a connection pool. 

When the `AsyncGroq` client instance is eventually garbage collected by Python (after the function-scoped event loop has already closed), the `__del__` destructor attempts to clean up this connection pool. Because `__del__` is synchronous, it instantiates an `aclose()` coroutine but has no running event loop to `await` it. 

When Python destroys this unawaited coroutine, it emits the `RuntimeWarning`.

**Important:** This is a library-internal cleanup lifecycle issue. **No network requests are dropped, and no memory leaks occur** because the OS reclaims the closed sockets when the process exits.

## How We Handle It
Because the issue is deep within the Stainless API generator and `httpx`, it cannot be cleanly "fixed" from user code without monkey-patching.

Our solution is two-fold:
1. **Best-Effort Cleanup**: In `conftest.py`, we explicitly call `asyncio.run(llm_proxy.close())` at the end of the session to drain as much as we can.
2. **Warning Suppression**: In `pytest.ini`, we added regex filters to suppress this exact, known warning so it doesn't fail our strict test pipeline:

```ini
filterwarnings =
    ignore:coroutine '.*[Cc]lient.*\.aclose' was never awaited:RuntimeWarning
    ignore:coroutine 'BaseApiClient\.aclose' was never awaited:RuntimeWarning
```

**Title:** `RuntimeWarning: coroutine 'AsyncClient.aclose' was never awaited` when AsyncGroq client is garbage collected

**Description:**
**Describe the bug**
When using the `AsyncGroq` client within a scoped `asyncio` event loop (such as in `pytest-asyncio` with function-scoped loops), a `RuntimeWarning` is emitted during garbage collection:

```text
RuntimeWarning: coroutine 'BaseApiClient.aclose' was never awaited
```
*(Depending on GC ordering, it sometimes manifests as `AsyncClient.aclose was never awaited`)*

This occurs because the event loop is already closed by the time the `AsyncGroq` instance is garbage collected. The `__del__` destructor attempts to clean up the connection pool but instantiates an `aclose()` coroutine that can no longer be awaited.

**To Reproduce**
Steps to reproduce the behavior:
1. Create a `pytest` suite using `pytest-asyncio` with `asyncio_default_fixture_loop_scope = function`.
2. Instantiate `client = AsyncGroq(api_key="...")` inside a test.
3. Allow the test to finish (the function-scoped event loop closes).
4. When the garbage collector eventually cleans up the `AsyncGroq` client, the `RuntimeWarning` is thrown.

**Expected behavior**
The client should either cleanly tear down its `httpx` transport via a `weakref.finalize` hook (which is loop-safe), or gracefully catch and suppress the instantiation of the `aclose` coroutine inside `__del__` if `asyncio.get_event_loop().is_closed()` is true.

**Additional context**
I am currently working around this by using `pytest.ini` filterwarnings:
```ini
filterwarnings =
    ignore:coroutine '.*[Cc]lient.*\.aclose' was never awaited:RuntimeWarning
```
Since this SDK is generated by Stainless API, the fix likely needs to be applied to the `BaseApiClient` template inside the Stainless generator to ensure `__del__` doesn't leak unawaited coroutines when no loop is running.
